# apps/ui

The Next.js UI, built as a static export and run in the Tauri webview (or, for
development and testing, a plain browser). Three panes: navigation on the left,
the current entity in the middle, open secondaries on the right.

## Data

- **The UI holds its own replica of the graph**: `crates/wasm` compiled to
  WASM, loaded from a snapshot at startup. Every query is answered locally and
  every edit applies locally; the shell is sent updates a moment later. Nothing
  the user types waits on IPC.
- **`lib/graph.ts` is the one place that touches the replica.** Reads are kept
  until the next edit (every edit clears the cache), so what a component reads
  is stable between edits. **Typing notifies subscribers after a pause and
  structure changes notify at once**, so a block isn't rebuilt per keystroke;
  `settle()` delivers a pending notification, and runs before a block stops
  being edited so it never shows its old text.
- **Backends** (`backend-tauri.ts`, `backend-memory.ts`) are chosen at runtime.
  Outside the app the graph is a made-up one in memory, built through the same
  replica, and reset on reload. **Its IDs differ on every load**, so tests
  can't keep an ID across a reload, and anything remembered by ID (Recents)
  must cope with it no longer existing.
- `lib/wasm` is generated by `pnpm ui wasm` and not committed. `dev`, `build`
  and `typecheck` run it first.

## Routing and boundaries

- **View state is the URL**: `/entity/?id=<main>&open=<a>,<b>` (`lib/nav.ts`).
  A static export can't enumerate entities for path segments, and the right
  pane is a list, not a route.
- Reading the URL suspends, so each pane, and each secondary within the right
  pane, has its own `Suspense` and error boundary (`Region`): a slow or broken
  one holds up nothing else. A card's header sits outside its content's
  boundary so it can always be closed.
- **The graph only exists in the browser**, so pages that read it render
  inside `ClientOnly` and aren't prerendered; prerendering never has to wait
  for it.

## Editing

- **`EditableOutline` provides an `Editing` context** (which block is being
  edited, where the caret goes, the entity's blocks in reading order); an
  `Outline` outside one, such as in references, is read-only.
- **`BlockEditor` is a CodeMirror editor bound to one block.** What is typed
  goes in as the splice that was typed, last change first so offsets stay
  valid; changes from the graph come back as the smallest edit, marked
  `fromGraph` so they aren't sent again. **It reconciles against
  `graph.blockText`, never against props**, which can be a keystroke behind.
- **Keys act on the graph, then say where editing continues.** Moving blocks
  makes React remount them, so a key that moves the block being edited calls
  `edit(id, caret)` *before* the structural change so the new editor opens at
  the right place. Undo and redo are the graph's (`Mod-z` in the editor, and
  `UndoKeys` when no editor is focused); there is no editor-level history.
- Removing a focused editor fires a blur that isn't the user leaving, so
  `closing` is set in a layout effect (which runs before the DOM goes).
- IDs held by editing state go dead across an undo of a deletion; that just
  ends the edit.

- The main pane's title (`EditableTitle`) renames in place when the entity
  is `renamable`: Enter or leaving the field keeps it, Escape drops it. Side
  cards and the journals feed show plain titles.

## Rendering

`RenderedBlock` is how a block reads when not being edited: `splitBlock` takes
line properties out for chips and swaps inline ones for placeholder characters,
`remarkQuiddity` turns `[[links]]`, `((refs))` and the placeholders into custom
elements (in text only, so never in code), and `react-markdown` draws the rest.
Block text comes from other devices and is untrusted, so:

- **Don't add `rehype-raw` or render HTML strings.** Raw HTML shows as text.
- Only `http(s)` and `mailto` links are links, opened through
  `lib/open-external.ts`; anything else is inert text.
- **Images aren't fetched**: a remote image is a request to its author.

## Tests

Playwright, against the static export (`pnpm ui build`, then `pnpm ui test:e2e`).
Each test starts from the same made-up graph. `e2e/fixtures.ts` fails a test
if the page logs an error. Pitfalls:

- The sidebar repeats names (Favourites, Recents), so scope a link locator to
  `main` before `.first()`.
- On the in-memory graph a page reload starts over, so a test that has changed
  something must move by clicking (the sidebar), not `page.goto`.
- A block's rendered text is `[data-block-text]` and an editor is `.cm-content`.
- Typing `\n` presses Enter, which splits the block; use Shift-Enter for a
  newline. Press `Control+Shift+Z`, not `Control+Shift+z`: Playwright otherwise
  sends a lowercase `z` that no keyboard does.
